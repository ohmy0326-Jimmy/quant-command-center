# 總經週期與配置

第五頁「總經週期與配置」平時讀 Google 試算表 Quant_Database，試算表 id 是 `1nMpEaNcIqymaTHiqJDhMxm5gLzCWrlfk5wkpCMJMjGM`。沿用戰鬥艙既有的服務帳戶，只讀、不建立分頁、不寫入。側邊欄是第一頁到第四頁、第五頁總經週期、第六頁下單輔助。

讀取順序：試算表 → 倉庫 `data/macro_cycle.json` → 中性（槓桿 1.5 倍、現金 15%）。試算表快取 15 分鐘。單列不合法就略過並在畫面上警告。第六頁只用 15 分鐘內第五頁已經算好的結果，否則直接讀 JSON，不會為了預設值去抓行情或試算表。

自動指標只在打開第五頁時平行抓取，單項逾時約 8 秒，結果快取 1 小時。抓得到就覆寫試算表裡的自動項；抓不到就用該列的試算表分數，再沒有才用 JSON。

JSON 備援仍是 schema 1.0.0（`data/macro_cycle.schema.json`）。加總不寫進檔案，用指標分數現算。

| 欄位 | 規則 |

## 試算表分頁

請另開試算表編輯，不要從這個 App 建表。第一列必須就是下面的欄位名，順序可以不同，但不能少、不能改名。

### Macro_Score

一列一個指標。`indicator_id` 只能用下表的代號。

| 欄位 | 允許值 |
| --- | --- |
| `indicator_id` | `us_real_yield`、`hy_spread`、`vix`、`equity_ma`、`sox_trend`、`pmi`、`earnings_revisions`、`valuation`、`tw_activity` |
| `name` | 畫面上的名稱，可空白，空白就用程式內建名稱 |
| `score` | 整數 `-2`、`-1`、`0`、`1`、`2` |
| `source` | `auto` 或 `manual`（也接受 `自動`、`手動`） |
| `value` | 文字，可空白。自動項成功時會被觀測值覆寫 |
| `note` | 文字，可空白 |
| `updated_at` | `YYYY-MM-DD` |

| indicator_id | 名稱 | 誰打分數 |
| --- | --- | --- |
| `us_real_yield` | 美國實質利率 | 自動 |
| `hy_spread` | 高收益債利差 | 自動 |
| `vix` | 波動率 VIX | 自動 |
| `equity_ma` | 美股與台股年線 | 自動 |
| `sox_trend` | 費半趨勢 | 自動 |
| `pmi` | 製造業 PMI | 手動 |
| `earnings_revisions` | 企業獲利修正 | 手動 |
| `valuation` | 評價 | 手動 |
| `tw_activity` | 台灣景氣與出口 | 手動 |

範例列：`pmi,製造業 PMI,1,manual,ISM 49,新訂單仍弱,2026-10-29`

### Industry_Cycle

一列一個產業，預期 20 列。少了的產業會用倉庫 JSON 補上。

| 欄位 | 允許值 |
| --- | --- |
| `industry` | 產業名稱，不可空白、不可重複 |
| `cycle` | `復甦`、`成長`、`趨緩`、`衰退` |
| `direction` | `上行`、`持平`、`下行` |
| `stance` | `加碼`、`中性`、`減碼` |
| `tickers` | 代表股，逗號分隔。`2330` 與 `2330.TW` 視為同一檔，跨列不可重複 |
| `note` | 文字，可空白 |
| `updated_at` | `YYYY-MM-DD`。試算表不強制必須是 12 日；每月 12 日更新仍是作業習慣 |

範例列：`半導體設備,成長,上行,加碼,"ASML, AMAT, LRCX",設備維持加碼,2026-10-12`

| 指標 | 資料 | 分數 |
| --- | --- | --- |
| 美國實質利率 | FRED `DFII10`（10 年 TIPS，免 API key 的 CSV）。另外讀 `DGS10` 只為了顯示名目 10 年 | 約 63 個交易日的變化（百分點）：≤ -0.25 為 +2，≤ -0.10 為 +1，-0.10～+0.10 為 0，< +0.25 為 -1，其餘 -2。實質利率下降加分 |

製造業 PMI、企業獲利修正、評價、台灣景氣與出口沒有自動公式，只看試算表的 `score`。

## 九項多空分數

倉庫 JSON 的 `score.indicators` 固定 9 筆，只在試算表失效時使用。每筆：

| 欄位 | 規則 |
| --- | --- |
| `id` | 小寫代號，`^[a-z][a-z0-9_]*$`，不可重複。 |
| `name` | 畫面上的名稱。 |
| `score` | 整數，`-2` 到 `+2`。 |
| `example` | `true` 表示這格仍是示例，不是正式週報。 |
| `note` | 選填。示例請在文字裡寫明。 |

九項加總的範圍是 `-18` 到 `+18`。狀態門檻：

| 加總 | 狀態 |
| --- | --- |
| +9～+18 | 牛 |
| +4～+8 | 偏多 |
| -3～+3 | 中性 |
| -8～-4 | 偏空 |
| -18～-9 | 熊 |

目前種子檔九項都是示例，加總 `+1`，狀態是中性。門檻寫在 `macro_cycle.REGIME_BANDS`。

## 二十個產業

`industries.items` 固定 20 筆。每筆：

| 欄位 | 規則 |
| --- | --- |
| `id` | 穩定代號，不可重複。 |
| `name` | 產業名稱，不可重複。 |
| `cycle` | `復甦`、`成長`、`趨緩`、`衰退`。四象限就是這四個位置：左上復甦、右上成長、右下趨緩、左下衰退。 |
| `direction` | `上行`、`持平`、`下行`。上行往下一階段（順時針）靠，下行往回靠。 |
| `stance` | `加碼`、`中性`、`減碼`。 |
| `tickers` | 至少一檔代表股。全部產業加起來，去掉大小寫與 `.TW`、`.TWO`、`.US`、`.HK` 後不可重複。`2330` 與 `2330.TW` 是同一檔。 |
| `example` | `true` 表示整列都是示例。`false` 表示立場是目前配置。 |
| `note` | 選填。立場已定、但週期／方向／代表股仍是示例時，note 要寫清楚。 |

v1 種子裡，立場已定的是：

- 加碼：半導體設備、光通訊/CPO、重電電網、先進製程
- 中性：AI 算力
- 減碼：消費電子、生技醫療、記憶體

這八列的週期、方向與代表股仍是示例。其餘十二個產業整列都是示例。

## 對到第六頁的風控

只覆寫兩個既有欄位，使用者仍可在「風控規則設定」裡改，工作階段會留著。按「改回總經週期預設」會再帶入一次。

| 狀態 | 目標槓桿上限 | 最低現金水位 |
| --- | --- | --- |
| 牛 | 2.0 倍 | 10% |
| 偏多 | 1.8 倍 | 12% |
| 中性 | 1.5 倍 | 15% |
| 偏空 | 1.2 倍 | 22% |
| 熊 | 1.0 倍 | 30% |

對應畫面「目標槓桿上限（倍）」與「最低現金水位（%）」。第二階段槓桿不跟著改。

持倉代號用代表股對到產業。對得上才在代號旁邊顯示「產業 · 加碼／中性／減碼」；整列是示例的會再加上「（示例）」。對不上的不標。

## 怎麼改資料

1. 在 Quant_Database 維護 `Macro_Score` 與 `Industry_Cycle`。手動項每週改 `score` 與 `updated_at`。產業圖建議仍在每月 12 日改。
2. 不要從 App 建這兩個分頁，也不要為了每週數字改 `data/macro_cycle.json`。JSON 只在試算表壞掉時當備援。
3. 打開第五頁才會抓試算表與自動行情。第六頁若 15 分鐘內第五頁算過，就用那次結果；否則用 JSON，不會卡住。
4. 已開著的第六頁若要改回新預設，按「改回總經週期預設」。
