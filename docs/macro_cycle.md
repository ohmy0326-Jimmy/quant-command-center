第五頁「總經週期與配置」平時讀 Google 試算表 Quant_Database，試算表 id 是 `1nMpEaNcIqymaTHiqJDhMxm5gLzCWrlfk5wkpCMJMjGM`。沿用戰鬥艙既有的服務帳戶，只讀、不建立分頁、不寫入。側邊欄是第一頁到第四頁、第五頁總經週期、第六頁下單輔助。

讀取順序：試算表的 45 日內手動覆寫 → 自動或代理 → 中性（槓桿 1.5 倍、現金 15%）。倉庫 `data/macro_cycle.json` 的示例分數不計入總分，只在畫面上標成示例。試算表快取 15 分鐘。單列不合法就略過並在畫面上警告。第六頁只用 15 分鐘內第五頁已經算好的結果，否則直接讀 JSON，但示例分數仍然不計分，所以會落在中性。

自動指標只在打開第五頁時平行抓取，單項逾時約 8 秒，結果快取 1 小時。抓得到就覆寫試算表裡的自動項；抓不到就用該列的試算表分數，再沒有才用 JSON。

JSON 備援仍是 schema 1.0.0（`data/macro_cycle.schema.json`）。加總不寫進檔案，用指標分數現算。

### Industry_Cycle

一列一個產業，預期 20 列。少了的產業會用倉庫 JSON 補上。

| 欄位 | 允許值 |
| --- | --- |
| `industry` | 產業名稱，不可空白、不可重複 |
| `cycle` | `復甦`、`成長`、`趨緩`、`衰退` |
| `direction` | `上行`、`持平`、`下行` |

| `note` | 文字，可空白 |
| `updated_at` | `YYYY-MM-DD`。試算表不強制必須是 12 日；每月 12 日更新仍是作業習慣 |

| 欄位 | 允許值 |
| --- | --- |
| `week` | `YYYY-MM-DD` |

範例列：`2026-10-26,1,中性`

近 20 日相對強弱沒有做。第二頁的 ETF 對照是美股板塊，對不上這 20 個產業。

### 4 週趨勢（只讀）

`week` 是一週一個總分日期。4 週不是往上數 4 列。最新一週要對到 26～32 天前的那一筆，中間相鄰日期都在 5～10 天，而且窗口裡剛好 5 筆。4 週均線是這 5 筆的平均。4 週變化是最新總分減去約 28 天前那一筆。下跌達到 3 分是黃燈。缺週、重複、未來日期、總分不是 -18～18 的整數、狀態與總分對不上、樣本不足時，燈號是未知，不補 0、不插值，也不當成安全。

這盞燈是總經分數趨勢，不是淨值回撤。回撤停新倉仍是 -8%，降到 1 倍仍是 -12%。不改推播。

倉庫 `data/macro_cycle.json` 的 `history` 目前只有 2026-10-19 與 2026-10-26 兩週，而且分數是示例。試算表沒有可用歷史時畫面會標成示例，不能當回測。打開第五頁只讀 `Macro_Score_History`，不會把今天重算的總分寫回去。

每日淨值快照在淨值寫入之後，把台北當天的總分 upsert 到 `Macro_Score_History`（一天一列）。九項不齊就留空，不當 0，也不用這份示例補。第五頁讀到可用列之後，4 週趨勢會跟著變長。打開第五頁仍然不寫試算表。

門檻回測現在一律不可回測，也不產生績效數字。歷史表沒有每週九項的當時分數、公布日或可見版本。至少需要 52 個連續週，而且不能用今天修訂後的總經值回填。沒有調整黃燈的 3 分。

範例列：`半導體設備,成長,上行,加碼,"ASML, AMAT, LRCX",設備維持加碼,2026-10-12`

總分 = 已有指標的加權分數 / 已有權重 × 8.5。覆蓋率 = 已有權重 / 8.5。覆蓋率低於 70% 標「不完整」，槓桿不高於中性的 1.5 倍、現金不低於中性的 15%。低於 50% 直接用中性配置。這組中性數字就是 `REGIME_RISK` 裡的中性，沒有另寫一套。

產業週期在沒有 45 日內 `source=手動` 的列時，用產業 ETF 的 3 個月與 6 個月相對強弱。台股 ETF 對 `^TWII`，其餘對 `SPY`。兩段都正是成長，3 個月正、6 個月負是復甦，3 個月負、6 個月正是趨緩，兩段都負是衰退。畫面標「價格推估，非基本面」。沒有對應 ETF 的產業維持未知或倉庫示例，不假裝有基本面判斷。對照寫在 `macro_proxies.INDUSTRY_ETFS`。

`Macro_Score_History` 多一欄 `coverage`（0～1）。九項不齊時總分仍留空，覆蓋率照寫。既有三欄的分頁會在右邊補上這一欄。

## 對到第六頁的風控

只覆寫兩個既有欄位，使用者仍可在「風控規則設定」裡改，工作階段會留著。按「改回總經週期預設」會再帶入一次。

| 狀態 | 目標槓桿上限 | 最低現金水位 |
| --- | --- | --- |
| 牛 | 2.0 倍 | 10% |
| 偏多 | 1.8 倍 | 12% |
| 中性 | 1.5 倍 | 15% |
| 偏空 | 1.2 倍 | 22% |
| 熊 | 1.0 倍 | 30% |

對應畫面「目標槓桿上限（倍）」與「最低現金水位（%）」。第二階段槓桿不跟著改。

持倉代號用代表股對到產業。對得上才在代號旁邊顯示「產業 · 加碼／中性／減碼」；整列是示例的會再加上「（示例）」。對不上的不標。

## 怎麼改資料

1. 在 Quant_Database 維護 `Macro_Score` 與 `Industry_Cycle`。手動項每週改 `score` 與 `updated_at`。產業圖建議仍在每月 12 日改。
2. 不要從 App 建這兩個分頁，也不要為了每週數字改 `data/macro_cycle.json`。JSON 只在試算表壞掉時當備援。
3. 打開第五頁才會抓試算表與自動行情。第六頁若 15 分鐘內第五頁算過，就用那次結果；否則用 JSON，不會卡住。
4. 已開著的第六頁若要改回新預設，按「改回總經週期預設」。
